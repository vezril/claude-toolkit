# Frameworks, licences and shipping

## Choosing how to build

| Route | Formats out | Language | Pick it when |
|---|---|---|---|
| **VST 3 SDK** directly | VST3, plus AU, AUv3 and AAX through its wrappers | C++ (CMake) | You want no framework between you and the host, or you are writing a host |
| **JUCE 8** | VST3, AU, AUv3, AAX, LV2, standalone app | C++ (Projucer or CMake) | Several formats and a full GUI toolkit from one codebase; the most common commercial choice |
| **iPlug2** | VST2/3, AU, AUv3, AAX, CLAP, Web Audio Modules | C++ | A smaller, permissively licensed alternative to JUCE |
| **CLAP SDK** + clap-wrapper | CLAP, with VST3 and AUv2 generated by the wrapper | C/C++ | CLAP-first design (polyphonic modulation, thread-pool support) without giving up VST3 hosts |
| **nih-plug** | VST3, CLAP | Rust | You want Rust's memory safety for the DSP and plug-in glue |
| **DPF** (DISTRHO) | LV2, VST2, VST3, CLAP, AU | C++ | Linux-first or open-source projects |

Whatever you choose, the VST 3 rules in `vst3-development.md` still apply underneath, and the
audio thread rules apply everywhere.

| **JUCE 8** | AGPLv3, or the commercial JUCE EULA: Starter (free, up to about US$20k annual revenue), Indie (up to about US$300k), Pro (no cap) | `[CHECK]` JUCE forum summary of the tiers. The EULA text governs |
| **CLAP** | MIT | `[VERIFIED]` the CLAP repository |
| **AAX SDK** | Avid's developer agreement; release builds need PACE signing to load in retail Pro Tools | `[CHECK]` |
| **nih-plug** | ISC. Its VST3 output used to pull in GPLv3 bindings; the SDK's move to MIT may change that, so check the project's current README | `[CHECK]` |
| **iPlug2, DPF** | Permissive (zlib-style and ISC respectively) | `[CHECK]` |

The GPL question that shaped plug-in licensing for a decade ("a VST3 build under GPLv3 makes my
product GPL") no longer applies to the VST 3 SDK itself from 3.8. It still applies to any other
GPL or AGPL code you link, including JUCE under its AGPLv3 option.

## Format-specific notes

- **AU** comes from Apple's AudioToolbox. Build it through JUCE, iPlug2 or the VST 3 SDK's AU
  wrapper. Validate with Apple's `auval` (`auval -a` lists installed AUs; `auval -v <type>
  <subtype> <manufacturer>` tests one). Logic won't show an AU that fails validation.
- **AAX** needs an Avid developer account and the AAX SDK. Development builds run in Pro
  Tools' developer build; release builds must be PACE-signed.
- **CLAP** has no licence step. Validate with `clap-validator`. Its extras over VST3 include
  per-voice (polyphonic) modulation, a host-provided thread pool and explicit thread-safety
  annotations on every call.

## Signing and notarization on macOS

A plug-in is a bundle loaded into the host's process, so the host's entitlements apply. You
still sign and notarize the bundle (or the installer), or Gatekeeper can block it on users'
machines.

1. Join the Apple Developer Program and create a **Developer ID Application** certificate (for
   bundles) and a **Developer ID Installer** certificate (for `.pkg` installers).
2. Build a universal binary (arm64 + x86_64) and check it with `lipo -archs`.
3. Sign the bundle with the hardened runtime and a secure timestamp:

   ```bash
   codesign --force --options runtime --timestamp \
     --sign "Developer ID Application: Your Name (TEAMID)" MyPlugin.vst3
   ```

4. Notarize (a zip of the bundle, or the signed `.pkg`), then staple the ticket:

   ```bash
   xcrun notarytool submit MyPlugin.pkg --keychain-profile "notary" --wait
   xcrun stapler staple MyPlugin.pkg
   ```

5. Verify on a clean machine, or with `spctl --assess -vv --type install MyPlugin.pkg`.

The [[release-macos-spm-packaging]] skill and the apple-release-manager agent cover signing and
notarization in more depth. On Windows, Authenticode-signing the installer reduces SmartScreen
warnings; the plug-in DLL itself needs no signature to load.
